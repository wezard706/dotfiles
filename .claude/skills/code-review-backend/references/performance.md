# パフォーマンス — バックエンド（Rails）

## 対象範囲

クエリ効率・処理の重複・メモリ効率・同期非同期・取得範囲の妥当性。

## チェックリスト

## 前提

- **この処理は1リクエストあたり何回呼ばれ、どれだけのユーザーに影響するか**。頻度×影響範囲が小さいなら深追いしない
- **想定される最大のデータ量・同時実行数でも成立するか**

## データベース

- **N+1やループ内クエリなど、クエリ発行回数がデータ件数に比例していないか**
- **WHERE / JOIN / ORDER BY のアクセスパターンに対応するインデックスがあり、それが効く書き方か**
- **書き込みが1件ずつのループになっていないか**
- **トランザクションが長すぎないか。外部API、ジョブのenqueue、通知など、トランザクション内で外部へ副作用を出していないか**

## Rails / ActiveRecord

- **分割処理やページングをせずにメモリへ全件ロードしていないか**
- **早期にArray化して遅延評価を壊し、以降の絞り込み・集計・件数取得がRuby側に落ちていないか**
- **Ruby側で行っている絞り込み・集計・ソートをDBに寄せられないか。またはその逆**
- **コールバック・バリデーションに重い処理や問い合わせが紛れていないか**
- **同じ問い合わせ・同じ計算を繰り返していないか。メモ化やキャッシュで避けられないか**

## 計算量・メモリ

- **ループのネストやコレクション内の線形探索など、入力サイズに対する時間計算量が妥当か**
- **中間データの生成やサイズが非有界な入力の一括読み込みなど、入力サイズに対する空間計算量が妥当か**

## I/O・外部依存

- **外部呼び出しの回数がデータ件数に比例していないか**
- **タイムアウト・リトライ・上限が設定されているか**

## 非同期ジョブ・バッチ処理

- **外部通信・重い集計・大量書き込みを同期で行う必要があるか**
- **1回の実行が扱う量が有界で、中断されない長さに収まるか**
- **リトライや重複実行が起きる前提で冪等か**
- **並列度がDB接続数・レート制限と釣り合い、オンライン処理を圧迫しないか**
